## 2. 产品目标（最高原则）

### 2.1 四条核心原则
1. **人类最终负责**：所有投资决策必须由用户本人做出，AI 仅做辅助，不越权。
2. **可解释、可追溯**：任何结论、建议、交易记录必须标注来源或体系依据，并能回链到具体原则/资料编号。
3. **双向认知进化**：体系随学习持续生长（晶体化），AI 随实践校准（置信度回灌）。
4. **异常人工介入**：任何边界外动作必须停下并交人判断，绝不强推。

### 2.2 边界红线（违反即不合格）
- AI **无任何自主交易决策权**，交易记录只能人工录入。
- 所有结论/记录必须标注**来源或体系依据**（表单强制字段）。
- **不得做出任何收益承诺**；每屏底部必须有「人类最终负责」深色声明条。
- 单票上限 20%、单一行业 ≤ 40% 等已确认硬规则必须在体系中体现。

## 4. 模块清单（需求池）

### P0 — MVP 必须交付（11 个模块）

| # | 模块 | 核心功能 | 关键约束 |
|---|---|---|---|
| 1 | **首页全局看板** | 聚合「今天要处理」、4 张 KPI、六层认知体系卡片、双环操作系统、异常预警、最近备忘录、深色免责声明。 | 六层卡片可跳转；异常需人工确认；免责声明贯穿。 |
| 2 | **投资原则 L1** | 宪法级细分视图，只读。展示类别（赚钱逻辑/不碰什么/风险底线）、适用边界、认同原因。 | **无编辑入口**；数据来自原则卡片 IS 的宪法级标记。 |
| 3 | **原则卡片 IS** | 唯一权威原则源。支持增删改；字段含模块归属、置信度%、验证计划、状态（草稿/已采纳/已弃用）。 | 编号 `IS-YYYY-NNN`；AI 检索只查此表 + 错误库。 |
| 4 | **投资方法 L2** | 策略与方法库。字段含适用场景、前提假设、操作步骤、局限性、方法编号 `M-YYYY-NNN`、状态。 | 方法可关联原则 IS；状态分启用/草稿/待验证。 |
| 5 | **标的研究 L3** | 个股/行业/基金标准化档案。字段含商业模式、护城河、关键财务、风险点、估值区间、跟踪要点。 | 关联 IS/ERR 编号；KPI 区展示价格、估值分位等。 |
| 6 | **交易决策日志 L4** | 仅人工录入。8 列表格：日期、标的、方向、数量、成交价、金额、关联备忘录、状态。 | 红涨绿跌；边界外记录用 `warn-soft` 高亮；页头红色徽章「AI 无交易决策权」。 |
| 7 | **复盘与错误 L5** | 区分交易复盘与错误清单。错误有稳定 `ERR-YYYY-NNN`、分类（认知/心态/执行）、关联原则、复盘记录。 | 错误库可被备忘录引用；AI 按月汇总高频错误。 |
| 8 | **观察灵感 L6** | 宏观/行业/突发/灵感池。状态：待归档 / 已归档；来源标签；关联标的/方法/错误。 | 支持筛选（全部/待归档/已归档）；可归档到 L2/L3。 |
| 9 | **投资备忘录** | 决策前闸门。七要素 + 红队挑战 + 本笔信心% + 引用 IS/ERR 编号 + 5 步闸门 + 状态。 | 5 步闸门：信息完整 / 风险已识别 / 红队挑战 / 引用原则+错误 / 信心 ≥ 60%；未通过则阻塞提交。 |
| 10 | **三层记忆总览 + 双环回灌** | 展示 L1 核心原则、L2 体系版本、L3 学习档案；人类环 6 步 ↔ 三层记忆 ↔ AI 环 5 步的双向回灌关系图。 | L1 人类写入·AI 读取；L2 人类触发·AI 同步；L3 AI 索引·人类检索。 |
| 11 | **AI 协作协议面板** | 系统治理面板。展示四阶段能力（信息分拣/知识织网/智能检索/复盘分析）、六维解构框架、知识晶体化流程。 | 仅展示协议内容，固化行为契约；未来可扩展为 Agent 配置入口。 |

### 5.3 人机色彩分工
| 角色 | 颜色 | 应用场景 |
|---|---|---|

| 金融涨跌 | 红涨 `#E5484D` / 绿跌 `#15803D` | 涨跌幅、方向标签、收益数字 |

### 5.4 ID 体系（三色/四色视觉）
- **IS-ID**：Indigo 徽章（原则）
- **M-ID**：Ink-700 徽章（方法）
- **ERR-ID**：Amber 徽章（错误）
- **MEMO-ID**：Primary 徽章（备忘录）

### 5.5 交互与视觉约束
- **零 emoji**：所有状态/警示使用纯文字 + 语义底色（如 `warn-soft`）。
- **深色免责声明条**：每屏底部固定深色条，文案示例：
  > 「人类最终负责 · AI 仅辅助不越权 · 所有引用须标注来源 · 边界外决策必须人工确认」
- **本地化**：
  - 涨红跌绿（中国股市惯例）。
  - 货币符号：`¥` / `HKD` / `USD` / `CNY`。
  - 日期格式：`YYYY-MM-DD`。
- **布局框架**：顶部 TopBar（搜索 + AI 记忆状态 + 人类最终负责按钮）+ 左侧 Sidebar（六层导航 + 核心工作台）+ 主内容区（页头 + 卡片/表格）。

## 6. 数据模型要点

### 6.1 10 张表核心字段语义

| # | 表（模块） | 核心字段语义 |
|---|---|---|
| 1 | 投资原则 L1 | 类别（赚钱逻辑 / 不碰什么 / 风险底线）、适用边界、认同原因 |
| 2 | 投资方法 L2 | 适用场景、前提假设、操作步骤、局限性、方法编号 M-ID、状态 |
| 3 | 标的研究 L3 | 商业模式、护城河、关键财务、风险点、估值区间、跟踪要点、关联 IS/ERR |
| 4 | 交易日志 L4 | 基础字段 + 5 决策字段（市场环境、估值情况、心态、预期收益、止损位）、可关联备忘录 ID |
| 5 | 复盘与错误 L5 | 类型（交易复盘 / 错误清单）、分类（认知 / 心态 / 执行）、稳定 ERR-ID、关联原则、复盘记录 |
| 6 | 观察灵感 L6 | 标题、来源、摘要、状态（待归档 / 已归档）、关联标的 / 方法 / 错误 |
| 7 | 原则卡片 IS | 模块归属、原则置信度%、验证计划、状态（草稿 / 已采纳 / 已弃用）、编号 IS-ID |
| 8 | 资料-卡片索引 | 资料 → 原则/方法/标的 双向关联索引 |
| 9 | 体系变更日志 | 变更类型（`+` 新增 / `~` 修改 / `-` 删除 / 待验证）、描述、版本号、时间 |
| 10 | 投资备忘录 | 七要素 + 红队挑战 + 本笔信心% + 引用原则 IDs + 引用错误 IDs + 状态 |

### 6.2 ID 规则
- **原则卡片**：`IS-YYYY-NNN`（例：`IS-2026-001`）
- **错误条目**：`ERR-YYYY-NNN`（例：`ERR-2026-001`）
- **方法条目**：`M-YYYY-NNN`（例：`M-2026-001`）
- **投资备忘录**：`MEMO-YYYY-NNN`（例：`MEMO-2026-0023`）

### 6.3 投资备忘录七要素 + 决策约束

**七要素**：
1. 关联标的
2. 方向（拟买 / 拟卖 / 做多 / 做空）
3. 投资逻辑
4. 预期收益
5. 时间框架
6. 催化剂
7. 风险

**附加决策约束**：
- 红队挑战（必填：反对意见 / 反向证据）
- 退出条件
- 本笔信心%（≥ 60% 方可通过最后一步闸门）
- 引用原则 IDs（IS-ID）
- 引用错误 IDs（ERR-ID）
- 状态：草稿 / 已决策 / 已执行 / 已放弃
- 日期

## 9. 待确认问题

以下模块/内容当前以**占位/草稿状态**显示「待定」，需预留可填充入口，但不可阻塞 MVP 开发：

1. **投资哲学**：用户尚未提供完整表述，首页/ L1 区显示「待定 · 待后续对话提炼」。
2. **硬规则（宪法级）**：除已确认的单票 20% / 行业 40% 外，其余硬规则待补充。
3. **能力圈边界**：「在圈 = ？」「禁区 = ？」待用户定义；异常预警逻辑依赖此输入。
4. **多币种显示**：当前示例含 CNY / HKD / USD，是否需统一折算或按原币种展示？
5. **数据导出格式**：JSON / CSV / Markdown？优先 JSON 便于迁移。
6. **AI 协作协议的执行深度**：MVP 仅做协议展示，是否需要在备忘录提交时做前端规则校验（如引用 IS 数量 ≥ 1）？
